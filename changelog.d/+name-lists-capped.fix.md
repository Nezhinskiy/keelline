Every list of names a repository or its history can make as long as it likes now names at most
eight of them and says how many more there are. On summary lines, `--json` still carries every
name: the documents `keelline docs trail` listed with no declared state; the notes `keelline memory
index` could not read and the notes or `memory.index_extra` pointers it held back; the refused
keys on `keelline gate`'s `config:` line; the custom gates `keelline assess --builtin` left out;
the gates `keelline adopt promote` promoted and those still advisory; the offences `keelline
commit check` found; and, in `keelline bugs check --json`, the files claiming one identifier, each
of which past the first also has a finding of its own. `keelline init`'s note on an adopted
`keelline.toml`'s custom gates named five before counting and now names eight, like the rest.
Refusals with no `--json` are bounded the same way: the `docs/trail.toml` `[states]` keys that
name no document, counted in full, the first eight in sorted order, with a note that a re-run
after updating those names the rest; the groups of a memory store none of whose `memory.groups`
resolves, counted, with the reasons for the first eight; the gates a project runs, when `[keelline]
enforced` names one it does not; the unknown keys and sections of a `keelline.toml`; and the merge
bases that leave `keelline test attribute` undetermined. And a `[states]` key or a `[[theme]]`
label longer than 120 characters is named in a refusal by its first 120 characters and its length,
where one key of 200 000 characters used to make a line of 200 000 characters.
